# Downstream usability review

Chain-top check: can UX, architecture, and epics source-extract `prd.md` (plus `addendum.md` as non-FR depth) without inventing product law.

## Verdict

**Not cleanly.** Named UJs, a locked glossary, globally numbered FR/NFR/SM IDs, and a one-line portal sitemap are enough for UX to *start* Hosted Checkout Page (four states) and Merchant Portal nav. They are not enough for a clean handoff. Architecture and epics must invent Subscription exit (cancel / remove Client Record), when the first Obligation is minted, and will mis-file pay-time method choice if they walk §4 in document order. §8’s “phase-blockers: none” overstates extractability.

What holds: UJ-1…UJ-5 each have a named protagonist (Awa, Fatou, Adama, Awa, Awa). FR-1…FR-50, NFR-1…NFR-12, SM-1…SM-9 / SM-C1…SM-C4 are unique and every cited ID resolves. Addendum correctly refuses to be a second FR source.

## Findings

- **[critical]** No cancellation (or remove-Client) FR (§2.3 UJ-2, §4.3 FR-11, §4.4 FR-27/28, §4.5 FR-31, §18) — Pause (FR-27) and Skip (FR-28) are specified; cancel is only a *condition*. UJ-2, FR-11 consent copy (“PAUSE or cancel”), FR-31 STOP mapping, and webhook status `cancelled` all assume a Subscription can end. There is no FR for who may cancel, how (no ANNULER verb), effect on open Obligations / Standing Authorization / Client Record, or whether Session `cancelled` ≠ Subscription cancelled. “Merchant removes the Client Record” is likewise a STOP terminator with no FR. Resume after Pause is a consequence line, not an FR. *Fix:* Add FR-51 (Customer + Merchant cancel Subscription), FR-52 (Merchant remove Client Record), and either fold Resume into FR-27 or give it an FR; lock effects on open Obligation and billing SMS; add a glossary **Cancel**. Do not leave exit as copy-only.

- **[high]** FR-18 / FR-19 sit in the wrong feature and break numeric walk order (§4.3 → §4.4 FR-20…28 → §4.5 FR-18, FR-19, FR-29…) — IDs are contiguous 1–50 with no gaps or duplicates, but document order is not. **FR-19 (pay-time method choice)** is a Consent State Machine step (`method`), not a notification. Section-extractors and epic grouping will park it under SMS. It also duplicates FR-8 (Plan separated from Rail). **FR-18 (Invite SMS)** is thematically at home in §4.5 but its number implies it belongs after FR-17. UJ-1/UJ-2 cite these IDs before a sequential reader has seen them. *Fix:* Move FR-19 into §4.3 beside FR-10 (keep the ID); merge or cross-cite FR-8 ↔ FR-19 in one sentence so epics do not split “rail choice” twice. Leave FR-18 in §4.5 or renumber only if you accept a global ID churn — prefer keep-ID + relocate.

- **[high]** First Obligation birth is not extractable (§2.3 UJ-1, §4.2 FR-9, §4.3 FR-10/FR-14) — UJ-1 path: after invite, Awa “sees the Obligation.” UJ-1 resolution: Standing Authorization may still be *pending*. FR-9 says creating the first Obligation uses the same primitive. FR-10: abandoned sessions leave no *collected* Obligation (uncollected birth still open). FR-14: Session may pass “line items that become a Plan/Obligation.” Three readers can mint at invite, at consent, or at first due date. That is a domain-model fork, not a UX detail. *Fix:* One sentence on FR-9 (or a new FR): Obligation is created at {invite | consent | first due}, and Accueil may show {pending consent / next due} before collect. Drop “line items” or define them in the glossary.

- **[medium]** Glossary drift will fork UX copy and story names (§3 vs running prose) — Discipline rule: synonyms are a violation. Recurring leaks: **Client** / “first Client” / “Client row” vs **Client Record** (UJ-1 title and path); **retry inbox** vs **Failed-collection Retry Inbox**; **MoMo** (Take-rate, SM-9, FR-15 title) vs **Orange Money** / **Rail** (MoMo is not a glossary term); **receivables book** and **payout destination** are load-bearing IA/KYC nouns with no glossary entries; **Developer Merchant** vs one **Merchant** account; FR-17 “Payment status” / “Rail PAN” (card leftover) vs Collection Attempt / Session status; **Invite SMS** is an FR title, not a glossary sibling of SMS Invoice / SMS Receipt; **user** banned for Customer but used in §2 titles and NFR-1 “end users.” *Fix:* Add glossary rows for receivables book, payout destination, Invite SMS, MoMo (= mobile-money Rails, not a third product). Replace Client→Client Record in UJ-1. Replace Payment/PAN with glossary status names.

- **[medium]** IA is a sitemap, not enough object IA for UX start (§11, §22) — Surfaces table + “Accueil · Clients · Plans · Encaissements · Paramètres · Développeurs” and “linear four-state” checkout let UX open DESIGN.md. Missing for a first pass without invention: signup / first-sitting sequence (FR-2’s Plan → Client Record → invite); where Cash Mark-paid, Pause, Skip, cancel, and remove Client Record live (Accueil vs Encaissements vs Client detail); receivables-book columns vs Obligation detail (FR-39); KYC-hold chrome (banner vs Paramètres only); Staff PIN interrupt; Customer SMS as a verb list with no empty/unknown-text screen; French nav labels vs English glossary names. Late-fee compounding is already parked on UX in §8.4 — that is fine only if object IA exists. *Fix:* Expand §22 with (1) first-sitting steps, (2) Accueil primary objects, (3) action homes for cash / retry / Pause / Skip / cancel / remove, (4) checkout four named states = glossary machine. Keep it surfaces-not-screens.

- **[medium]** Lifecycle leftovers without FRs: write-off, refund, Resume (§2.3 UJ-4, §4.4 FR-27, §4.6 FR-34) — UJ-4 climax: owed until collected or written-off; “operator, not Customer self-serve.” FR-34 supports `refunded` / `written-off` as ledger states, “staff-only in MVP.” No actor, surface, or permission FR. Resume is required by FR-27 with “documented SMS/path” but no verb. Epics will either drop these or invent ops tools. *Fix:* If MVP, add a one-line FR (platform-ops write-off/refund; Customer/Merchant Resume). If not, `[NON-GOAL for MVP]` on write-off/refund and name the Resume verb.

- **[medium]** Incomplete UJ → FR maps (extract will under-scope stories) (§2.3) — Cited IDs all resolve; several path steps do not. UJ-1 path registers payout MSISDN (FR-38) and later Cash Mark-paid (FR-23) but capabilities omit both. UJ-2 uses PAUSE and names FR-13/FR-15/FR-27/FR-32 chrome and verbs without citing them. UJ-3 climax is live Orange `collected`/`settled` and Take-rate (FR-21, FR-35–37, FR-40) but the list stops at sandbox/webhook. UJ-4 uses Staff PIN (FR-4) and failure SMS (FR-29) uncited. Reverse “Realizes UJ-n” on FRs is denser than the UJ capability arrows. *Fix:* Make each UJ capability list the union of FRs that `Realizes` that UJ (or drop unused reverse refs).

- **[low]** Capability vs implementation leakage (§0 claim vs §4, §13, §18) — Most FRs stay at capability. Leaks that architecture should own, not copy as product law: FR-5 “Developers toggle”; FR-14 “line items”; FR-17 “Rail PAN/PIN”; FR-22 “enumerated CountryPack field”; NFR-6 “hashed at rest” / “shown once at create”; FR-40 “without an admin GUI.” Status vocabulary in §18 is an intentional capability lock — keep it. Addendum §2 (adapter counterparty, `createSession`) is correctly parked. *Fix:* Reword leaks to outcomes (Developers surface available; secrets unrecoverable; Rails are CountryPack data). Move hash-at-rest to addendum.

- **[low]** Assumptions Index misses two inlines (§9 vs NFR-2, §19) — Indexed FR-6 / FR-36 / FR-38 / FR-43 / FR-12 / FR-40 / late-fee match. Unindexed: NFR-2 “< 8 s on mid-3G”; §19 hosting may be outside BF. NFR-5 is cited on the FR-36 index line but not tagged inline. *Fix:* Append those two to §9.

- **[low]** Addendum §1 can poison extract if treated as peer source (`addendum.md` §1) — Header says not a second FR source. §1 still quotes system-idea “access a portal and choose preferred payment method,” which contradicts PRD pay-time method (FR-8/FR-19) and no Customer portal. *Fix:* One italic line under that quote: superseded by PRD Consent State Machine; method at pay time, no Customer account home.
